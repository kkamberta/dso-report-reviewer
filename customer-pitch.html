1. What is it?

A report reviewer agent for security scan outputs.

It does not replace scanners. It sits after scanners and converts noisy technical output into a consistent, reviewable security report.

Input

CI/CD XLSX reports from Black Duck, Coverity, Checkpoint CVE, Checkpoint Secret, and Checkpoint Threat sheets.

Processing

Applies app priority, scanner-specific rules, residual severity logic, remediation guidance, and structural validation.

Output

Annotated XLSX, executive markdown summary, and a queue of rows that require human approval before final sign-off.

2. Why should a customer have it?

Because raw scanner results do not tell engineering what to do next.

The value is not another scan. The value is consistent decision support after the scan finishes.

Reduce triage load

Security teams stop reading hundreds of repeated rows manually and focus on exceptions, critical assets, and policy decisions.

Improve consistency

The same severity and app-impact rules are applied to every row, every build, independent of analyst fatigue or skill gap.

Make remediation usable

Scanner text like "upgrade package" becomes practical guidance such as package-manager commands or Docker rebuild direction when evidence supports it.

Keep accountability

The agent drafts recommendations, but risky severity changes and uncertain rows remain under human review.

Speed up release gates

Pipeline teams get a fast risk summary after each scan instead of waiting days for manual security review.

Create audit evidence

Each report keeps the decision, severity, remediation, and validation status in a repeatable format.

3. Where can it be used?

The most realistic deployment is a container receiving a webhook when pipeline scans finish.

4. How it works

A small pipeline with a clear human control point.

The agent is useful because the deterministic checks and approval gates are built into the workflow.

1

Scan finishes

Existing scanner exports the report as a build artifact.

2

Webhook received

Pipeline sends job metadata and artifact URL to the reviewer container.

3

Agent reviews

Rows are normalized, prioritized, enriched with remediation, and assigned draft residual severity.

4

Validation runs

Coverage, valid severity values, and required output fields are checked automatically.

5

Human signs off

Security reviews flagged rows before the report drives acceptance, tickets, or release decisions.

Common customer questions

Answers your boss can use in the room.

Use these as talk tracks when the customer asks about fit, security, accuracy, and ownership.

Is this replacing our security scanners?

No. It consumes scanner output after Black Duck, Coverity, or Checkpoint finish. The scanners still detect issues; this reviewer turns findings into prioritized, actionable review output.

Can it decide risk automatically?

It can draft residual severity and remediation, but final risk acceptance stays human-gated. Critical downgrades, severity jumps, validation failures, and uncertain rows are flagged for review.

Where does it run?

As an internal container service. The pipeline sends a webhook with artifact metadata after scan completion. The service downloads the report, processes it, and stores outputs in an internal job folder.

What data does it need?

Scanner report, project or app code, priority mapping, and optional build metadata. More accurate environment context improves residual severity quality.

How do we trust the output?

The system validates row coverage and output shape independently of the model. The semantic decisions are transparent in the XLSX and remain reviewable by security engineers.

What happens when the agent is wrong?

The reviewer can override the row. Repeated corrections should become deterministic rules or config, so the same correction does not need to be repeated manually.

Can it create Jira or ServiceNow tickets?

Yes, but that should be phase two. V1 should produce reviewed artifacts first. Ticket creation should happen only after dedupe, ownership, and approval rules are stable.

What is the smallest valuable rollout?

Start with one pipeline, one application group, and one report format. Prove time saved, review quality, and false-positive handling before expanding to ticket automation.

Pitch line

DSO Report Reviewer does not add another scanner. It turns existing scan results into consistent, actionable, human-approved remediation decisions at CI/CD speed.
